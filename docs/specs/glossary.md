# Glossary — HostFlow System

Этот документ определяет термины и обозначения, используемые во всех модулях HostFlow. Глоссарий является источником истины для бизнес-логики, API, документации и работы ИИ-агентов.

---

## Основные сущности

- **Candidate** — водитель, потенциальный сотрудник транспортной компании. Главная сущность системы. Имеет персональные данные, контактную информацию, статус в пайплайне, набор документов и связь с компанией или вакансией.  
- **Vacancy** — вакансия от клиента (компании). Определяет требования, тип занятости, ставки и доступных менеджеров. Может быть активной или закрытой.  
- **Document** — документ, подтверждающий личность, квалификацию или разрешение на работу кандидата. **Document Instance** в Document Hub: файл + `document_type` + поля. Не путать с **Requirement**.  
- **Requirement (требование)** — бизнес-обязательство («подтвердить legal stay»), не файл. Process Engine принимает решения по **requirement satisfaction**. Канон: [ADR-016](architecture/ADR-016-requirement-evidence-document-separation.md), [`requirement-evidence-model-p0.md`](platform/requirement-evidence-model-p0.md).  
- **Accepted Evidence (допустимое подтверждение)** — каталог способов закрыть Requirement (visa, karta pobytu, combined EU license, …). Меняется при изменении правил без смены Requirement.  
- **Chosen Evidence / Candidate Evidence** — факт: *каким* документом *этот* кандидат закрывает Requirement (`requirement_code` + `evidence_variant_code` + `document_id`). Хранится отдельно от Document Instance.  
- **Company** — транспортная фирма‑клиент, нанимающая водителей. Имеет контакты, страну регистрации, размер автопарка и связанные вакансии.  
- **Lead** — входящая заявка из рекламных источников (Meta, TikTok, сайт и т.д.), из которой может автоматически создаваться кандидат.  
- **Tenant** — отдельный клиент SaaS‑платформы (например, агентство). Каждый tenant полностью изолирован при помощи RLS.  
- **Manager** — пользователь с ролью “Recruiter” или “Viewer”, управляющий кандидатами своего tenant.  
- **Owner** — администратор tenant, имеющий полный доступ, включая управление пользователями и настройками.  
- **Stage** — этап в пайплайне кандидата. Определяет состояние и правила переходов.  
- **Reminder** — системное напоминание о сроках документов, задачах, собеседованиях.  
- **Event** — системное событие, фиксирующее изменение (создание кандидата, обновление статуса, истечение документа).

## Бизнес‑термины транспорта и трудоустройства

- **Świadectwo Kierowcy (ŚK)** — свидетельство водителя для граждан стран вне ЕС, подтверждающее право работать в Польше или ЕС.  
- **Code 95** — сертификат, подтверждающий квалификацию профессионального водителя.  
- **Red Paper** — подтверждение подачи документов на визу (tymczasowy dokument).  
- **Work Permit (Zezwolenie)** — разрешение на работу, выданное воеводой.  
- **Visa** — национальная или шенгенская виза для водителя из третьих стран.  
- **Trial Period** — испытательный срок после выезда в рейс.  
- **Base Client** — транспортная компания, на базе которой водитель проходит оформление или обучение.

## Технические и архитектурные термины

- **RLS (Row‑Level Security)** — механизм PostgreSQL, обеспечивающий изоляцию данных между tenant‑ами.  
- **RBAC (Role‑Based Access Control)** — ролевая модель доступа в HostFlow.  
- **CRUD** — операции создания, чтения, обновления и удаления данных.  
- **Seed / Seeder** — скрипты для заполнения БД начальными данными (например, ролями).  
- **Migration (Alembic)** — изменение схемы БД, создаваемое через Alembic.  
- **Model (SQLAlchemy)** — ORM‑модель таблицы БД.  
- **Schema (Pydantic)** — контракт данных между API и клиентом.  
- **Webhook** — HTTP‑вызов, получаемый системой из внешнего источника (например, форма Meta).  
- **Spec (Specification)** — живое описание логики и структуры системы.  
- **Canon (Канон)** — закреплённый стандарт поведения, от которого нельзя отступать без ревизии.  
- **Event Bus** — внутренняя шина событий между сервисами (например, document.expired).  
- **Reminder Engine** — подсистема планировщика напоминаний (Redis/Cron).  
- **Audit Log** — журнал действий пользователей и системных событий.

## Интеграции и внешние источники

- **Meta / Facebook / TikTok Leads** — рекламные формы, поступающие через webhook в HostFlow.  
- **Meta Leads Admin** — раздел админки (`/admin/meta-leads`) для управления credential’ами Meta, маппингом объявлений и ручной маршрутизацией лидов.  
- **WhatsApp Business API** — интеграция для коммуникации с кандидатами.  
- **Email Gateway** — SMTP/IMAP‑модуль для уведомлений.  
- **External Carrier Portal** — возможный внешний интерфейс для компаний‑партнёров (Roadmap).

## Системные роли и доступы

| Роль | Права | Примечание |
|------|--------|------------|
| **Owner** | Полный доступ, управление пользователями и tenant‑настройками | Только 1 на tenant |
| **Manager / Recruiter** | CRUD кандидатов, документов, вакансий | Основная рабочая роль |
| **Viewer** | Только просмотр кандидатов и вакансий | Без изменений данных |
| **System / Bot** | Автоматические напоминания, интеграции, задачи | Не отображается в UI |

## Сокращения и внутренние обозначения

| Сокращение | Расшифровка | Контекст |
|-------------|-------------|-----------|
| **ATS** | Applicant Tracking System | тип системы HostFlow |
| **MVP** | Minimum Viable Product | версия, запущенная в продакшн |
| **Spec** | Specification | файл в `docs/specs/**` |
| **Seed** | Инициализация данных | `make seed` |
| **RLS** | Row‑Level Security | изоляция tenant‑ов |
| **RBAC** | Role‑Based Access Control | контроль доступа |
| **CRUD** | Create, Read, Update, Delete | базовые операции |
| **ETL** | Extract, Transform, Load | процессы переноса данных |
| **DTO** | Data Transfer Object | используется в API |
| **IDEMPOTENT** | повторяемый без побочных эффектов запрос | важно для webhook’ов |
