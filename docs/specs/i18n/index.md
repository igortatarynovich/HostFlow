# 🌐 HostFlow i18n Registry

> Каноническая спецификация локализации. Используется для всех модулей (backend, frontend, уведомления, напоминания, документы).

---

## 1. Ключевые принципы
- Source язык — `en`. Все остальные локали наследуются от него.
- Локали, обязательные к поддержке: `en`, `ru`, `pl`.
- Все текстовые значения (UI, уведомления, письма, push, webhooks) должны ссылаться на ключи из реестра.
- Пустые строки и значения `null` в переводах запрещены. Явные плейсхолдеры обязательны.

> 🔎 Доп. материалы: аудит и предложение ключей для модуля Candidate Intake & Docs — `docs/specs/i18n/candidate_intake_i18n_step1.md`.

---

## 2. Формат и нейминг ключей

### 2.1 Структура ключа
```
<module>.<page_or_domain>.<block>.<label>
```

**Примеры**
- `documents.workflow.step.ordered`
- `leads.import.csv.validation.phone_invalid`
- `notifications.documents.expiring.title`

### 2.2 Правила
- Используем только латиницу (a-z), цифры и `_` внутри сегмента.
- Разделитель сегментов — `.` (точка). Двойные точки запрещены.
- Зарезервированные сегменты:
  - `common.*` — общие элементы UI.
  - `notifications.*` — шаблоны уведомлений (in-app, email, webhook).
  - `errors.*` — системные ошибки.
- Каждому ключу сопоставляется metadata: `scope` (ui, email, webhook), `module`, `updated_at`, `owner`.

---

## 3. Формат реестра

Хранение в `json`/`yaml` с единым источником (`en`). Пример фрагмента:

```json
{
  "documents": {
    "workflow": {
      "step": {
        "ordered": "Ordered",
        "submitted": "Submitted",
        "approved": "Approved",
        "delivered": "Delivered"
      }
    }
  }
}
```

Переводы (`ru`, `pl`) следуют той же структуре. Неиспользуемые ключи удалять нельзя без миграции UI.

---

## 4. Фолбэк цепочка

1. Пользовательская локаль (`user.locale`, если есть).
2. Локаль тенанта (`tenant.default_locale`).
3. Source (`en`).
4. Literal ключа (выводим `documents.workflow.step.ordered`), если перевод отсутствует — допускается только в dev-режиме.

> Никаких молчаливых пустых строк: отсутствие ключа фиксируется в логах наблюдаемости (`observability.md`) и подлежит исправлению до релиза.

---

## 5. Версионирование и релизы

- Файлы переводов версионируются вместе с кодом (git).
- Для релиз-кандидатов (`RC`) действует политика **string freeze**: новые ключи запрещены, допускается только правка ошибок.
- Каждому релизу соответствует тэг `i18n/<version>` с snapshot переводов.
- Регрессия переводов покрывается smoke-тестом: проверяем, что ключи из `en` присутствуют во всех обязательных локалях.

---

## 6. Инструменты и управление

- CLI `scripts/i18n_sync.py`:
  - валидация нейминга;
  - сравнение структур (`en` → `ru/pl`);
  - выгрузка реестра для UI.
- Tenant Admin Console:
  - включение/отключение локалей;
  - добавление кастомных переводов (с префиксом `tenant.<tenant_id>.*`).
- Кастомные переводы хранятся в базе и накладываются поверх базовых ключей (merge при загрузке).

---

## 7. Чек-лист для изменений

- [ ] Новый UI-текст оформлен как ключ, присутствует в `en`.
- [ ] Добавлены переводы в `ru`, `pl` (можно временно = English, но не пусто).
- [ ] Обновлён changelog i18n (если ключ публичный).
- [ ] Запущен `scripts/i18n_sync.py --validate`.
- [ ] Требования к фолбэку не нарушены (ручная проверка при code review).
