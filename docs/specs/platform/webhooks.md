

# Webhooks & API Keys (Вебхуки и ключи API)

## Цель
Модуль предназначен для интеграции HostFlow с внешними системами (CRM, ERP, маркетинговые платформы, сервисы аналитики) через управляемые вебхуки и API-ключи.  
Основная задача — обеспечить безопасную, гибкую и масштабируемую модель обмена событиями и данными между HostFlow и внешними клиентами.

## Основные функции
- Создание и управление вебхуками.
- Подписка на системные события (candidate.created, document.expired, invoice.paid и др.).
- Настройка формата и структуры полезной нагрузки (payload).
- Управление API-ключами для внешних интеграций.
- Ограничение доступа по ролям и tenant.
- Поддержка перезапуска и повторной доставки событий.
- Логирование всех запросов и ответов вебхуков.
- Настройка retry-политики и dead-letter очередей.

## Модель данных
- `webhooks`: `id, tenant_id, name, target_url, secret, active_events[], is_active, created_at, updated_at`
- `webhook_logs`: `id, webhook_id, event_type, payload, response_code, attempts, status, last_attempt_at`
- `api_keys`: `id, tenant_id, name, key_hash, scope, created_by, created_at, last_used_at, is_active`
- `api_key_logs`: `id, api_key_id, request_path, response_code, ip, timestamp`

## Логика работы
1. Пользователь создаёт вебхук и выбирает события, на которые он подписан.
2. При возникновении события система формирует payload и отправляет POST-запрос на `target_url`.
3. Если ответ ≠ 2xx, система повторяет отправку согласно retry-политике (3, 10, 30 минут).
4. При многократной неудаче событие попадает в dead-letter очередь.
5. API-ключи используются для аутентификации запросов к публичному API.
6. Все вызовы логируются в `api_key_logs` с указанием IP и timestamp.

## API (черновик)
- `POST /webhooks` — создать вебхук.
- `GET /webhooks` — список вебхуков.
- `PATCH /webhooks/{id}` — обновить вебхук.
- `DELETE /webhooks/{id}` — удалить.
- `GET /webhooks/logs` — логи вызовов.
- `POST /api-keys` — создать API-ключ.
- `GET /api-keys` — список ключей.
- `DELETE /api-keys/{id}` — отозвать ключ.
- `GET /api-keys/logs` — активность по ключам.

## UI / UX
- Раздел **Интеграции → Вебхуки** в панели администратора.
- Таблица вебхуков с состоянием (Активен / Ошибка / Неиспользуется).
- Просмотр логов по каждому вебхуку.
- Генерация и копирование API-ключей с ограниченным сроком действия.
- Цветовая индикация:
  - 🟢 Активен
  - 🟡 Предупреждения (ошибки доставки)
  - 🔴 Отключен / Ошибка

## Интеграции
- **Candidates:** события создания, обновления, статусов.
- **Leads:** `lead.received`, `lead.assigned`, `lead.needs_routing`, `lead.converted`, `lead.failed`, `lead.rejected` (см. `modules/leads.md`).
- **Documents:** истечение сроков и загрузка новых файлов.
- **Invoicing:** создание, оплата, отмена счетов.
- **Additional Services:** заказы и статусы услуг.
- **Compliance:** завершение проверок.
- **Scheduler:** создание и завершение событий.
- **Audit Log:** хранение всех системных вызовов вебхуков и API.

## Безопасность
- Все вебхуки подписываются HMAC-SHA256 с использованием `secret`.
- Проверка подписи на стороне получателя.
- Ограничение количества запросов (rate limit).
- API-ключи хранятся только в хэшированном виде.
- Возможность ограничить ключ по IP и сроку действия.
- Проверка RLS по `tenant_id`.

## Тест-кейсы
- Создание вебхука → при событии `candidate.created` отправляется payload.
- Ответ сервера ≠ 2xx → повтор через 3, 10, 30 минут.
- Проверка подписи вебхука → HMAC совпадает.
- API-ключ с ограничением по IP → доступ запрещён при несоответствии.
- Проверка RLS — вебхуки и ключи видны только в рамках tenant.
