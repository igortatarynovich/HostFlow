0. Цель и подход

Цель:
Сделать полноценный сканер документов для водителей в HostFlow, который:
	•	работает стабильно в браузере (мобилка + десктоп),
	•	даёт «скановое» качество (выравнивание, контраст, чёткость),
	•	автоматом проверяет качество и отбраковывает мусор,
	•	плотно интегрирован с модулем документов кандидата.

Подход:
	•	Фронт → только UX + работа с камерой + отправка снимков на сервер.
Без wasm-OpenCV в браузере, максимум лёгкие JS-эвристики.
	•	Бэк → полноценная обработка в Python + OpenCV:
	•	поиск контура документа,
	•	выравнивание (perspective transform),
	•	улучшение качества,
	•	оценка качества (резкость, яркость, обрезанные края и т.п.).

1. Список типов документов и пресеты

Нужно завести централизованный список пресетов, чтобы UI и CV говорили на одном языке.

1.1. Пресеты документов (backend enum + shared config на фронте)

Пример (можно расширять):
	•	id_card — Национальный ID / karta pobytu
	•	aspect_ratio ≈ 1.59 (85.6 × 54 мм — формат ID-1)
	•	pages: front, back
 	•	driver_license — права
 	•	aspect_ratio: как у ID (можно та же константа)
 	•	pages: front, back
 	•	passport_main — разворот с фото
 	•	aspect_ratio ≈ 1.4–1.5 (ориентировочно, но важнее полнота)
 	•	pages: spread (одна страница)
 	•	passport_all_pages — все страницы (если требуется)
 	•	aspect_ratio: свободный
 	•	pages: page_1, page_2, ... (динамично)
 	•	tacho_card — карта тахо (как ID)
 	•	adr_certificate
 	•	medical_certificate
 	•	psychology_test
 	•	и т.д.
 	•	Если нужны дополнительные коды (например, id_front, id_back, passport_page_3), добавляем их по аналогии в пресетах/фронте/бэке, чтобы везде использовались те же идентификаторы.

Для каждого пресета храним:
{
  "code": "id_card",
  "name": "ID card",
  "expected_pages": ["front", "back"],
  "aspect_ratio": 1.59,
  "min_resolution": { "width": 1200, "height": 800 },
  "max_angle_deviation_deg": 10,
  "min_brightness": 0.2,
  "max_brightness": 0.9,
  "min_sharpness": 100.0  // variance of Laplacian
}
Бэк хранит это в БД или в конфиге, фронт тянет через API /api/v1/scan/presets или жёстко зашиваем shared-константу (лучше через API).

2. API-бэкенд: эндпоинты сканера

2.1. Создание сессии сканирования

POST /api/v1/scan-sessions

Body:
{
  "candidate_id": "<uuid>",
  "document_type": "id_card",
  "document_kind_id": "<id типа документа из HostFlow Docs>",
  "expected_pages": ["front", "back"] // опционально, можно взять из пресета
}

Ответ:
{
  "id": "<scan_session_id>",
  "status": "in_progress",
  "document_type": "id_card",
  "pages": [
    { "id": null, "code": "front", "status": "pending" },
    { "id": null, "code": "back", "status": "pending" }
  ],
  "upload_limits": {
    "max_pages": 10,
    "max_file_size_mb": 10
  }
}

2.2. Загрузка страницы (сырое фото)

POST /api/v1/scan-sessions/{session_id}/pages

Форма multipart/form-data:
	•	file: image/jpeg или image/png
	•	page_code: "front" | "back" | "extra_n" (строка)
	•	rotation: целое (0, 90, 180, 270) — как фронт «понимает», в каком положении кадр.
	•	(опционально) crop_hint: JSON с четырьмя точками (если фронт всё же даёт свою рамку):
  {
  "crop_hint": {
    "points": [
      { "x": 0.1, "y": 0.1 },
      { "x": 0.9, "y": 0.1 },
      { "x": 0.9, "y": 0.9 },
      { "x": 0.1, "y": 0.9 }
    ]
  }
}

Ответ:
{
  "page_id": "<uuid>",
  "status": "uploaded"
}

2.3. Запуск обработки (можно и автотриггером в фоне)

POST /api/v1/scan-sessions/{session_id}/process

Без тела или с опцией:
{ "reprocess": false }

Ответ:
{
  "id": "<scan_session_id>",
  "status": "processing"
}

Обработка выполняется асинхронно (task queue / background job), но для ТЗ достаточно: «после вызова этого эндпоинта бэк инициирует обработку всех загруженных страниц».

2.4. Получение статуса и результатов

GET /api/v1/scan-sessions/{session_id}

Ответ:
{
  "id": "<scan_session_id>",
  "status": "done",  // in_progress | processing | done | failed
  "document_type": "id_card",
  "pages": [
    {
      "id": "<page_id>",
      "code": "front",
      "status": "ok", // ok | needs_review | rejected | error
      "quality_score": 0.86,
      "issues": ["slightly_blurry"],
      "preview_url": "https://.../processed_front.jpg"
    },
    {
      "id": "<page_id>",
      "code": "back",
      "status": "rejected",
      "quality_score": 0.3,
      "issues": ["cut_edges", "too_dark"],
      "preview_url": "https://.../processed_back.jpg"
    }
  ],
  "can_attach_to_candidate": true
}

2.5. Подтверждение и привязка к кандидату

POST /api/v1/scan-sessions/{session_id}/attach

Бэк:
	•	создаёт записи в таблице документов кандидата,
	•	привязывает конечные файлы (PDF/JPEG) как нормальные документы,
	•	ставит source = 'scanner',
	•	создаёт связь с document_kind_id.

Ответ:
{
  "attached_documents": [
    {
      "candidate_document_id": "<uuid>",
      "page_code": "front",
      "url": "https://.../final_front.pdf"
    },
    {
      "candidate_document_id": "<uuid>",
      "page_code": "back",
      "url": "https://.../final_back.pdf"
    }
  ]
}

3. Внутренняя обработка на бэке (Python + OpenCV)

3.1. Общий pipeline по странице

Для каждой загруженной страницы:
	1.	Загрузка файла
	•	Берём из S3 / локального сториджа исходный original.jpg.
	2.	Базовая нормализация
	•	конвертация в BGR/GRAY
	•	выравнивание по rotation (0/90/180/270)
	3.	Поиск документа (контур)
	•	Gaussian blur (для устранения шума)
	•	Canny edge detection
	•	findContours → выбираем крупнейший четырёхугольный контур.
	•	если находим:
	•	анализируем соотношение сторон → сравниваем с пресетом aspect_ratio
	•	считаем площадь контура относительно кадра (документ не должен занимать 5% кадра).
	•	если не находим → помечаем issue: "doc_not_found".
	4.	Перспективное выравнивание
	•	cv2.getPerspectiveTransform + cv2.warpPerspective
	•	приводим к целевому размеру, соответствующему пресету:
	•	например: ширина = 1600 px, высота = округление по аспекту.
	5.	Улучшение качества
	•	выравнивание освещения: CLAHE или адаптивная коррекция контраста.
	•	приведение к grayscale + опциональная бинаризация (для чётких ч/б документов).
	•	лёгкое повышение резкости (unsharp mask).
	6.	Оценка качества
	•	резкость: variance of Laplacian → sharpness_score
(ниже порога → issue "too_blurry").
	•	яркость/контраст: анализ гистограммы
(слишком тёмно/слишком светло).
	•	обрезанные края:
	•	по краям кадра не должно быть текста, уходящего за край.
	•	можно сделать простую эвристику: оставить 5–10% поля по краю.
	•	шум/артефакты (по желанию).
	7.	Присвоить статус
	•	если все метрики выше порогов → status = "ok".
	•	если есть лёгкие проблемы, но документ читаемый → status = "needs_review".
	•	если тёмный, размытый, контур не найден → status = "rejected".
	8.	Сохранение результата
	•	processed_image.jpg (и/или сразу page.pdf).
	•	метрики качества в таблицу scan_pages.

3.2. Таблицы БД (упрощённо)

scan_sessions:
	•	id
	•	candidate_id
	•	document_type
	•	document_kind_id
	•	status (in_progress / processing / done / failed)
	•	created_at, updated_at

scan_pages:
	•	id
	•	scan_session_id
	•	page_code (front/back/extra_n)
	•	original_file_path
	•	processed_file_path
	•	status (uploaded/processing/ok/needs_review/rejected/error)
	•	quality_score (float)
	•	issues (JSONB массив строк)
	•	meta (JSONB — углы, aspect_ratio, rotation и т.п.)
	•	created_at, updated_at

4. Фронтенд: поведение сканера

4.1. Вход в сканер

Фронт вызывает:
	•	POST /api/v1/scan-sessions → получает session_id и список ожидаемых страниц.
	•	Открывает экран сканера.

4.2. Экраны / состояния
	1.	Запрос доступа к камере
	•	Если отказ → показать инструкцию “разреши камеру / загрузка из галереи (позже)”.
	2.	Экран съёмки
	•	Верх: название типа документа (например, “Паспорт — разворот с фото”).
	•	Центр: видеопоток камеры.
	•	Поверх: рамка с нужным aspect_ratio:
	•	для id_card, driver_license, tacho_card: горизонтальный прямоугольник с соотношением 1.6.
	•	для паспорта: другой ratio.
	•	Нижняя панель:
	•	прогресс: “Шаг 1 из 2 (лицевая сторона)”
	•	подсказки (сменяются): “Выровняй документ по рамке”, “Избегай бликов” и т.п.
	•	кнопки:
  "Сделать снимок"
  "Отмена"


	3.	Авто-детект (без OpenCV)
	•	Можно сделать простой JS:
	•	считать «стабильность» кадров по разнице соседних кадров (если мало изменений — считаем стабильно).
	•	если стабильность выше порога N кадров подряд → автоматически триггерим capture().
	•	Это создаёт ощущение “автоспуска”, без CV.
	4.	Предпросмотр страницы
	•	Показать сделанное фото в рамке.
	•	Возможности:
	•	применить визуальный фильтр (по сути CSS/Canvas):
  "Оригинал"
  "Ч/Б"
  "Усиленный"
  повернуть (90°)
  "Переснять" (возврат к камере)
  "Сохранить страницу" → отправка через /scan-sessions/{id}/pages

  	5.	Список страниц сессии
	•	После сохранения → экран:
	•	миниатюра страницы,
	•	статус: “Ожидает обработки / Отправлено”.
	•	Кнопки:
	•	“Снять следующую сторону” (если есть ещё ожидаемые в пресете),
	•	“Готово → Отправить на обработку”.

4.3. После отправки
	•	Фронт вызывает POST /scan-sessions/{id}/process.
	•	Периодически опрашивает GET /scan-sessions/{id}.
	•	Показывает пользователю:
	•	зелёный чек — всё ок,
	•	жёлтый — “документ под вопросом, HR перепроверит”,
	•	красный — “фото плохого качества, сделай заново” (возможность вернуться в камеру только для конкретной страницы).

5. Интеграция с HostFlow Docs

После attach:
	•	В карточке кандидата в разделе “Документы”:
	•	отобразить документ(ы) с пометкой “Получено через сканер”,
	•	иконку статуса качества (ок/нужен пересмотр/плохой).
	•	При открытии документа:
	•	показывать обработанный вариант (как скан),
	•	дать ссылку/кнопку “Открыть оригинальное фото” (на случай ошибок CV).

6. Нефункциональные требования
	•	Размер файла: до 10 МБ на одну страницу (мобильные фото) → бэк при загрузке уменьшает до разумного размера (например, max 2500 px по длинной стороне).
	•	Формат: принимаем image/jpeg, image/png. Храним processed в JPEG или PDF.
	•	Производительность:
	•	одна страница должна обрабатываться < 1 секунды при типичном разрешении (1920×1080) — проверять на продовом железе.
	•	обработка выполняется в фоне, UI не должен висеть.
	•	Безопасность:
	•	никакого unsafe-eval, никаких wasm-воркеров в браузере.
	•	только стандартный JS + Canvas.
	•	Логи:
	•	логировать причины rejected страниц (для аналитики — какие проблемы у водителей самые частые).
