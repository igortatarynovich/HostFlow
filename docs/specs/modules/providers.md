

# Providers Network (Сеть провайдеров услуг)

## Цель
Модуль предназначен для управления базой внешних провайдеров, оказывающих услуги кандидатам и компаниям: медицинские комиссии, психотесты, курсы Code95, ADR, переводы, проживание и т.д.  
Основная цель — обеспечить прозрачную, централизованную и автоматизированную работу с партнёрами, упростить бронирование и контроль качества.

## Основные функции
- Реестр провайдеров по категориям услуг.
- Управление расписанием и доступными слотами.
- Интеграция с модулем **Scheduler** для записи кандидатов.
- Учёт тарифов, SLA и комиссий.
- Контроль качества и рейтинги.
- Ведение договоров и документов с провайдерами.
- Автоматическое создание заказов на услуги и выставление счетов.
- Геолокационный поиск ближайших провайдеров.

## Модель данных
- `providers`: `id, tenant_id, name, category, address, city, region, country, contact_name, phone, email, website, rating, notes, is_active, created_at`
- `provider_services`: `id, provider_id, service_type, price, currency, sla_days, available_slots, commission_rate, is_active`
- `provider_docs`: `id, provider_id, doc_type, file_id, expiry_date, verified, created_at`
- `provider_reviews`: `id, provider_id, candidate_id, rating, comment, created_at`
- `provider_contracts`: `id, provider_id, contract_number, start_date, end_date, file_id, status`

## Логика работы
1. Провайдер добавляется вручную или через импорт.
2. После верификации он становится доступен для выбора в заказах и расписаниях.
3. При создании услуги (в Additional Services) выбирается провайдер и слот.
4. После выполнения услуги создаётся запись о завершении и выставляется счёт.
5. Система собирает рейтинг и отзывы кандидатов.
6. Провайдеры с низким рейтингом могут быть автоматически деактивированы.

## API (черновик)
- `GET /providers` — список провайдеров.
- `GET /providers/{id}` — детали провайдера.
- `POST /providers` — создать провайдера.
- `PATCH /providers/{id}` — обновить информацию.
- `GET /providers/{id}/services` — услуги провайдера.
- `POST /providers/{id}/services` — добавить услугу.
- `GET /providers/search?city=Poznan&type=medical` — поиск по фильтрам.
- `POST /providers/{id}/review` — добавить отзыв.

## UI / UX
- Раздел **"Провайдеры"** в панели администратора.
- Карточка провайдера с табами: Информация, Услуги, Документы, Отзывы.
- Отображение рейтинга и истории взаимодействий.
- Кнопка «Создать заказ» прямо из карточки.
- Цветовая индикация:
  - 🟢 Активный
  - 🟡 Проверяется
  - 🔴 Неактивен / истёк контракт

## Интеграции
- **Additional Services:** выбор провайдера при создании заказа.
- **Scheduler:** использование слотов расписания.
- **Invoicing:** автоматическое выставление счетов за оказанные услуги.
- **Compliance:** хранение договоров и проверка сроков.
- **Audit Log:** запись всех изменений и действий с провайдерами.
- **Import / Export:** загрузка базы провайдеров.

## Безопасность
- Доступ к редактированию имеют только пользователи с ролью `OWNER`.
- Контракты и документы провайдера хранятся в зашифрованном виде.
- Проверка RLS по `tenant_id`.

## Тест-кейсы
- Добавление нового провайдера и услуги → доступна для выбора в заказах.
- Создание бронирования через Scheduler → слот блокируется.
- Истечение срока действия контракта → провайдер деактивируется.
- Оставление отзыва кандидатом → рейтинг обновляется.
- Проверка RLS — доступ только для пользователей tenant.
