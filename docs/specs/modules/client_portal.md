

# Client Portal (Портал клиента)

## Цель
Предоставить клиентам (транспортным компаниям и их подразделениям) доступ к собственным контрактам, кандидатам, документам и счетам, а также возможность взаимодействовать с агентством без необходимости использовать полную версию HostFlow.

## Основные пользователи
- **Client Manager (Менеджер клиента)** — управляет вакансиями, подтверждает кандидатов, следит за выполнением контрактов.
- **Client HR / Recruiter** — работает с кандидатами, видит статусы документов, добавляет комментарии.
- **Client Accountant** — видит счета и оплаты, может скачивать документы.
- **Client Viewer** — только просмотр (например, директор или владелец компании).

## Доступ и безопасность
- Доступ через защищённый портал (уникальная ссылка + пароль / SSO / одноразовый токен).
- Каждому пользователю портала назначается `client_user` с ограниченным доступом.
- Tenant-level isolation: клиент видит только свои компании, вакансии, контракты и кандидатов.
- Действия логируются в `client_audit_log`.

## Функционал портала
- Просмотр списка **контрактов** и их статусов.
- Отображение активных **вакансий** и связанных кандидатов.
- Просмотр **прогресса подбора** (по этапам pipeline).
- Подтверждение / отклонение кандидатов.
- Комментирование кандидатов и заказов.
- Доступ к документам (кандидатов, контрактов, счетов).
- Просмотр и скачивание **счетов и актов**.
- Уведомления о новых кандидатов и изменениях статусов.
- Возможность **создания заказа** (заявки на подбор водителей).
- Интеграция с **Candidate Portal** (кандидат видит часть данных, связанные с клиентом).

## Модель данных
- `client_users`: `id, company_id, email, role(client_manager|client_hr|client_accountant|client_viewer), password_hash, is_active`
- `client_audit_log`: `id, client_user_id, action, target_type, target_id, created_at, ip`
- Использует связи с `companies`, `contracts`, `vacancies`, `candidates`, `invoices`.

## API (черновик)
- `POST /client-portal/login` — авторизация.
- `GET /client-portal/contracts` — список контрактов клиента.
- `GET /client-portal/vacancies` — активные вакансии и кандидаты.
- `POST /client-portal/candidates/{id}/approve` — подтверждение кандидата.
- `POST /client-portal/candidates/{id}/reject` — отклонение с комментарием.
- `GET /client-portal/invoices` — список счетов.
- `GET /client-portal/files/{id}` — скачивание документа.
- `POST /client-portal/orders` — создание нового заказа.

## UI / UX
- Панель со сводкой: активные контракты, кандидаты, статус выполнения (% закрытых позиций).
- Канбан кандидатов по этапам.
- Таблица документов и счетов.
- Карточка кандидата (только чтение, но с комментариями и кнопкой «Подтвердить»).
- История коммуникаций и действий.
- Мобильная адаптация под простую работу с планшета.

## Уведомления
- Email и WhatsApp (через интеграцию) при появлении новых кандидатов или счётов.
- Уведомления внутри портала при изменениях статусов.
- Настройка частоты и типа уведомлений.

## Тест-кейсы
- Авторизация клиента с токеном → доступ только к его данным.
- Client Manager подтверждает кандидата → уведомление агентству.
- Client Accountant скачивает инвойс → событие в audit log.
- Клиент создаёт заказ → заявка появляется в админке агентства.
- Проверка RLS — клиент не видит данные других компаний.
