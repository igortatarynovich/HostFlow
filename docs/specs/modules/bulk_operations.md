

# Bulk Operations (Массовые операции)

## Цель
Обеспечить возможность массового выполнения однотипных действий для ускорения работы рекрутеров и администраторов. Модуль предназначен для оптимизации операций с документами, кандидатами и уведомлениями.

## Поддерживаемые объекты
- Кандидаты
- Документы
- Напоминания и уведомления
- Контракты
- Счета и платежи (ограниченно)

## Основные функции
- Массовое утверждение или отклонение документов.
- Массовое назначение рекрутера/ответственного менеджера.
- Массовое создание напоминаний или уведомлений.
- Массовое обновление статусов кандидатов.
- Массовая генерация инвойсов или актов (по контрактам/услугам).
- Массовая отправка email/WhatsApp уведомлений кандидатам или клиентам.

## Модель данных
- `bulk_operations`: `id, tenant_id, operation_type, target_type, filters, items_count, created_by, created_at, status, result_summary`
- `bulk_operation_items`: `id, bulk_operation_id, target_id, status, error_message`
- Статусы операций: `pending`, `processing`, `completed`, `failed`, `cancelled`.

## Логика работы
1. Пользователь формирует фильтр (например, все кандидаты без медосмотра).
2. Система отображает превью выбранных объектов и подсчитывает количество.
3. Пользователь подтверждает выполнение операции.
4. Задача отправляется в очередь обработки.
5. После завершения генерируется отчёт (`result_summary`) с количеством успешных и неудачных операций.

## API (черновик)
- `POST /bulk` — создать массовую операцию.
- `GET /bulk/{id}` — получить состояние операции.
- `GET /bulk` — список последних операций.
- `POST /bulk/{id}/cancel` — отменить операцию.
- `GET /bulk/{id}/report` — отчёт по выполнению.

## UI / UX
- Вкладка **"Массовые действия"** доступна пользователям с ролью `OWNER` и `RECRUITER`.
- Предварительный просмотр выбранных элементов перед подтверждением.
- Индикация выполнения (progress bar + статус).
- Возможность скачать отчёт об операции (CSV).
- Цветовая маркировка:  
  - 🟢 Успешно  
  - 🟠 Частично  
  - 🔴 Ошибки  

## Интеграции
- **Documents:** approve/reject/upload нескольких документов.
- **Candidates:** массовая смена этапов, менеджеров или тегов.
- **Invoicing:** массовое создание счетов на основе контрактов/услуг.
- **Notifications:** рассылка напоминаний кандидатам или клиентам.
- **Audit Log:** каждая операция фиксируется как единый блок с детализацией по элементам.

## Тест-кейсы
- Массовое одобрение 100 документов → статус `completed`, отчёт содержит успешные операции.
- Попытка массового действия без прав → ошибка `403`.
- Отмена операции в процессе → статус `cancelled`.
- Массовое создание напоминаний → генерируется событие `reminders.created_bulk`.
- Проверка RLS — операции только в рамках `tenant_id`.
