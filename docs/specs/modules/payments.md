

# Payments (Онлайн-оплаты)

## Цель
Модуль обеспечивает приём и обработку онлайн-платежей от физических и юридических лиц.  
Используется для оплаты счетов, дополнительных услуг и комиссий.  
Интегрируется с внешними платёжными провайдерами (Stripe, Revolut, Przelewy24, PayPal).

## Основные функции
- Оплата счетов (инвойсов) онлайн.
- Поддержка частичных и полных оплат.
- Создание платёжных ссылок (payment links).
- Вебхуки для отслеживания статусов транзакций.
- Хранение истории платежей и квитанций.
- Возвраты и сторнирование платежей.
- Поддержка нескольких валют.
- Возможность автоматического выставления счетов при оплате услуг.

## Модель данных
- `payments`:  
  `id, tenant_id, invoice_id, candidate_id, company_id, provider, payment_link, amount, currency, status, reference_id, created_at, confirmed_at, refunded_at`
- `payment_providers`:  
  `id, name, api_key, is_active, supported_currencies, created_at`
- `payment_logs`:  
  `id, payment_id, provider_event, raw_data, created_at`

## Логика работы
1. При создании счёта (из модуля **Invoicing**) система создаёт платёжную ссылку.
2. Клиент или кандидат открывает ссылку и производит оплату через выбранного провайдера.
3. После оплаты провайдер отправляет вебхук → система обновляет статус платежа.
4. Если сумма совпадает со счётом → статус `paid`, иначе `partial`.
5. Возможен возврат средств вручную или через API.
6. Все события фиксируются в `payment_logs` и `audit_log`.

## API (черновик)
- `POST /payments` — создать платёж вручную.
- `GET /payments` — получить список платежей.
- `GET /payments/{id}` — получить детали платежа.
- `POST /payments/{id}/refund` — оформить возврат.
- `GET /payments/{id}/link` — получить платёжную ссылку.
- `POST /payments/webhook/{provider}` — обработка уведомлений от провайдера.

## UI / UX
- Раздел **"Платежи"** в админке и порталах.
- Отображение истории оплат по кандидатам, компаниям и счетам.
- Цветовая индикация:
  - 🟢 Оплачено
  - 🟡 Частично
  - 🔴 Ожидает оплаты / Ошибка
- Кнопка "Отправить ссылку на оплату" (email / WhatsApp).
- Возможность выгрузки отчёта по платежам (CSV).

## Интеграции
- **Invoicing:** создаёт платёжные ссылки по инвойсам.
- **Additional Services:** генерирует счета и автоматически перенаправляет на оплату.
- **Candidate Portal:** кандидаты могут оплачивать услуги и видеть статус.
- **Client Portal:** клиенты оплачивают счета онлайн.
- **Compliance:** учёт платёжной истории при проверках.
- **Audit Log:** запись всех транзакций и вебхуков.

## Безопасность
- Поддержка HTTPS, JWT и верификации вебхуков.
- Все ключи API шифруются и хранятся в Vault.
- Проверка суммы и валюты перед подтверждением оплаты.
- RLS — каждая транзакция доступна только пользователям своего tenant.
- Маскирование персональных данных в логах (email, IBAN).

## Тест-кейсы
- Создание платежа по инвойсу → формируется ссылка.
- Оплата через Stripe → статус `paid`, квитанция сохранена.
- Частичная оплата → статус `partial`.
- Возврат → статус `refunded`.
- Проверка RLS — видимость только в рамках tenant.
