# Onboarding (Ввод в работу и передача кандидата клиенту)

---

## Регистрация и первый вход (post-registration onboarding)

После входа пользователь должен пройти онбординг, если у его тенанта ещё нет ни одной компании.

- **Проверка:** `GET /api/v1/onboarding/status` возвращает `{ "onboarding_required": true }`, если у тенанта нет ни одной **operating company** (первого собственного профиля tenant).
- **Действие:** при `onboarding_required === true` фронт редиректит на `/app/onboarding/company`. Пользователь заполняет форму: название своей компании и тип компании — **Агентство**, **Прямой работодатель** или **Услуги**. Отправка `POST /api/v1/companies` с полями `name`, `company_type` и `company_role='operating'`. Бэкенд при создании первой operating company выставляет `Tenant.type` и business profile tenant.
- После успешного создания компании редирект в основное приложение (например `/app/overview`); онбординг считается пройденным (при следующем запросе status у тенанта уже есть компании, `onboarding_required: false`).

Каноническая интерпретация:
- Этот шаг создает **рабочий профиль компании подписчика** (issuer/acting company), от лица которой пользователь и его команда выполняют операции в CRM.
- Выбор `company_type` обязателен и определяет базовую модель продукта: presets, funnels, labels, analytics baseline, first-value path и lead/client semantics.
- Дополнительные реквизиты (legal/billing/bank/branding) можно заполнить позже в `My Company`, но для фактур обязательны как минимум налоговый номер (NIP/Tax ID), юридический адрес и банковский счет отправителя.

Правило лицензии:
- лимит подписки применяется к количеству **operating companies** tenant;
- client companies не считаются собственными профилями tenant и не должны расходовать этот лимит.

Связанный код: `backend.app.api.v1.onboarding` (GET status), `backend.app.modules.companies.crud.create_company` (`company_role`, `company_type`, license limit, обновление Tenant.type), фронт: экран онбординга компании и редирект в AppShell по статусу.

# Onboarding (Ввод в работу и передача кандидата клиенту)

## Цель
Модуль предназначен для координации процесса выхода кандидата на работу у клиента после трудоустройства, включая передачу документов, проверку готовности, коммуникацию с флит-менеджерами и контроль первых дней на базе.  
Главная задача — обеспечить прозрачный, контролируемый и документированный переход от этапа "трудоустроен" до "активный сотрудник".

## Основные функции
- Формирование чек-листа действий при выходе кандидата.
- Проверка наличия всех необходимых документов и разрешений.
- Назначение ответственных лиц (координатор, флит-менеджер, HR клиента).
- Создание задач и напоминаний (привоз, обучение, подписание документов).
- Ведение журнала коммуникаций и результатов адаптации.
- Возможность выгрузки акта приёма-передачи кандидата.
- Автоматическая смена статуса кандидата после успешного завершения onboarding.

## Модель данных
- `onboarding_records`:  
  `id, tenant_id, candidate_id, company_id, status, start_date, end_date, coordinator_id, fleet_manager_id, readiness_score, notes`
- `onboarding_tasks`:  
  `id, onboarding_id, title, description, assigned_to, due_date, status, completed_at`
- `onboarding_logs`:  
  `id, onboarding_id, event_type, message, created_at, created_by`

## Логика работы
1. После этапа "трудоустроен" система автоматически создаёт запись `onboarding_record`.
2. Формируется стандартный чек-лист задач (проживание, инструктаж, медосмотр, документы клиента).
3. Координатор и флит-менеджер получают уведомления.
4. По мере выполнения задач рассчитывается `readiness_score` (готовность кандидата).
5. После выполнения всех задач статус меняется на `completed`.
6. Возможно ручное завершение с комментарием и актом приёма-передачи.

## API (черновик)
- `POST /onboarding` — создать процесс адаптации.
- `GET /onboarding/{id}` — получить детали.
- `PATCH /onboarding/{id}` — обновить статус или задачи.
- `GET /onboarding?candidate_id={id}` — получить процесс кандидата.
- `POST /onboarding/{id}/complete` — завершить процесс.
- `GET /onboarding/reports` — получить статистику адаптации.

## UI / UX
- Раздел **"Онбординг"** в карточке кандидата и компании.
- Отображение прогресса выполнения задач (progress bar).
- Возможность добавлять собственные задачи или чек-листы.
- Интеграция с календарём для напоминаний.
- Цветовая индикация:
  - 🟡 В процессе
  - 🟢 Завершено
  - 🔴 Проблемы / Требует внимания

## Интеграции
- **Candidates:** автоматическое создание процесса после трудоустройства.
- **Companies:** доступ флит-менеджеру и HR клиента.
- **Documents:** проверка наличия всех обязательных документов перед выходом.
- **Tasks / Notifications:** создание напоминаний и уведомлений.
- **Compliance:** запись статуса готовности в журнал соответствия.
- **Invoicing:** возможность добавления стоимости услуги онбординга.
- **Audit Log:** фиксация всех изменений и действий.

## Тест-кейсы
- Создание записи онбординга после этапа `трудоустроен`.
- Выполнение всех задач → статус `completed`.
- Пропущенная задача → `readiness_score` ниже 100%.
- Ручное завершение процесса с комментарием.
- Проверка RLS — видимость только для пользователей tenant и участников процесса.
