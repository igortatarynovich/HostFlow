

# Logistics (Логистика и организация поездок)

## Цель
Модуль предназначен для организации транспортировки кандидатов (водителей) от страны происхождения до базы клиента, включая бронирование билетов, трансферов, проживания и отчётность по перемещению.  
Основная цель — автоматизировать и отслеживать путь кандидата, минимизировать ручное управление поездками и снизить потери времени при релокации.

## Основные функции
- Создание маршрута кандидата (страна отправления → страна назначения → база клиента).
- Бронирование билетов (авиа, автобус, поезд) через интеграции.
- Учёт трансферов и встреч на границе или базе.
- Организация проживания (гостиница, база клиента, апартаменты).
- Создание ваучеров на поездки и проживание.
- Отслеживание статуса поездки в реальном времени.
- Автоматическая генерация отчётов по передвижениям и расходам.
- Возможность назначения ответственного координатора.

## Модель данных
- `logistics_trips`:  
  `id, tenant_id, candidate_id, company_id, start_location, end_location, departure_date, arrival_date, transport_type, status, coordinator_id, total_cost, created_at`
- `logistics_segments`:  
  `id, trip_id, type (flight/train/bus/transfer), provider, booking_ref, departure_time, arrival_time, cost, status`
- `logistics_accommodation`:  
  `id, trip_id, location, check_in, check_out, provider, cost, notes`
- `logistics_vouchers`:  
  `id, trip_id, type (ticket/accommodation/meal/other), file_id, issued_at`

## Логика работы
1. После подтверждения найма кандидат получает статус `planned_for_relocation`.
2. Рекрутер или координатор создаёт новую поездку (`logistics_trip`).
3. Добавляются сегменты маршрута (авиа, автобус, поезд, трансфер).
4. При необходимости бронируется проживание.
5. Система формирует ваучеры и загружает их в карточку кандидата.
6. После завершения поездки статус обновляется на `arrived_to_client_base`.
7. Все расходы фиксируются и могут быть выставлены клиенту через модуль **Invoicing**.

## API (черновик)
- `POST /logistics/trips` — создать поездку.
- `GET /logistics/trips/{id}` — получить детали поездки.
- `PATCH /logistics/trips/{id}` — обновить статус или детали.
- `GET /logistics/trips?candidate_id={id}` — список поездок кандидата.
- `POST /logistics/trips/{id}/segments` — добавить сегмент маршрута.
- `POST /logistics/trips/{id}/accommodation` — добавить проживание.
- `GET /logistics/reports` — получить отчёт по логистике.

## UI / UX
- Раздел **"Логистика"** в карточке кандидата и компании.
- Хронологическая лента маршрута с сегментами и статусами.
- Возможность загрузки билетов и подтверждений проживания.
- Отдельная вкладка для координатора с календарём выездов и прибытия.
- Цветовая индикация:
  - 🟡 В процессе планирования
  - 🟢 Выполняется
  - 🔵 Завершено
  - 🔴 Отменено

## Интеграции
- **Candidates:** автоматически создаёт поездку после этапа `планируем приезд`.
- **Companies:** доступ к списку приезжающих кандидатов.
- **Additional Services:** покупка билетов и проживания как платная услуга.
- **Invoicing:** автоматическое создание счёта за поездку/проживание.
- **Notifications:** напоминания о датах отправления и прибытия.
- **Audit Log:** запись всех действий по логистике.

## Безопасность
- Все бронирования и ваучеры видимы только пользователям, связанным с компанией/агентством.
- Персональные данные кандидатов маскируются в отчётах.
- Проверка RLS по `tenant_id`.

## Тест-кейсы
- Создание поездки и добавление сегментов → статус `planned`.
- Добавление проживания и ваучера → сохраняются корректно.
- Завершение поездки → статус `arrived_to_client_base`.
- Отчёт по всем поездкам месяца → корректная сумма расходов.
- Проверка RLS — данные доступны только в пределах tenant.
