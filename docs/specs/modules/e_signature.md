

# E-signature (Электронная подпись)

## Цель
Модуль обеспечивает юридически значимое подписание документов в системе HostFlow, интегрируясь с внешними провайдерами (Autenti, DocuSign, Adobe Sign).  
Используется для контрактов, офферов, инвойсов, актов и других документов, требующих подтверждения обеих сторон.

## Основные функции
- Отправка документов на подпись через интеграцию с провайдером.
- Поддержка многостороннего подписания (агентство, клиент, кандидат).
- Отслеживание статусов подписи (`pending`, `signed`, `declined`, `expired`).
- Хранение сертификатов и доказательств подписи.
- Автоматическая генерация финальной версии документа (PDF) после подписи.
- Возможность встроенного предпросмотра статуса в карточках контракта, инвойса или кандидата.

## Модель данных
- `sign_requests`: `id, tenant_id, provider, document_id, document_type, status, created_by, created_at, updated_at`
- `sign_participants`: `id, sign_request_id, email, role, signed_at, declined_at, verification_method`
- `sign_audit`: `id, sign_request_id, event_type, event_time, metadata`

## Логика работы
1. Пользователь инициирует подписание документа.
2. Система создаёт `sign_request` и передаёт файл в интеграцию.
3. Провайдер отправляет приглашения участникам.
4. После подписания всех сторон система получает вебхук и обновляет статус на `signed`.
5. Финальная версия PDF сохраняется в `files` и прикрепляется к исходному объекту (контракт, инвойс и т.д.).
6. Все события подписания сохраняются в `sign_audit`.

## API (черновик)
- `POST /signatures` — создать запрос на подпись.
- `GET /signatures/{id}` — получить статус подписи.
- `POST /signatures/{id}/cancel` — отменить запрос.
- `GET /signatures/providers` — список доступных провайдеров.
- `GET /signatures/{id}/audit` — журнал событий.

## UI / UX
- В карточках документов отображается блок **Подписи**:
  - Статус по каждой стороне (иконки + таймлайн).
  - Кнопки: «Отправить на подпись», «Отменить», «Скачать подписанный PDF».
- Уведомления по email всем участникам.
- Цветовая индикация:
  - 🟡 Ожидает подписи
  - 🟢 Подписано
  - 🔴 Отклонено / Истёк срок

## Интеграции
- **Approvals:** автоматически инициирует подписание после финального одобрения.
- **Invoicing:** инвойсы и акты могут автоматически направляться клиенту на подпись.
- **Contracts:** обязательная электронная подпись для активации контракта.
- **Document Templates:** создаёт PDF-документы для подписания.
- **Audit Log:** фиксирует каждое действие, включая получение вебхуков.

## Безопасность
- Хранение сертификатов подписи и метаданных в зашифрованном виде.
- Поддержка KYC верификации участников (по email, SMS или ID).
- Все действия подписания логируются с IP и timestamp.

## Тест-кейсы
- Отправка контракта на подпись → статус `pending`.
- Получение вебхука о подписании → статус `signed`, создаётся файл PDF.
- Один участник отклонил подпись → статус `declined`.
- Истечение срока подписи → статус `expired`.
- Проверка RLS: доступ только в рамках `tenant_id`.
