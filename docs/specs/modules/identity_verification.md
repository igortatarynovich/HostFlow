# Identity Verification (Проверка личности)

## Цель
Обеспечить проверку личности кандидатов и клиентов при приёме на работу и верификации документов.  
Модуль интегрируется с OCR, selfie-verification и базами проверки подлинности документов.  
Используется для снижения риска подделок и ускорения валидации документов.

## Основные функции
- Сканирование и автоматическое распознавание паспортов и водительских удостоверений (OCR).
- Сравнение фотографии документа с selfie кандидата (Liveness + Face Match).
- Проверка сроков действия документа.
- Сверка данных с внутренней карточкой кандидата (ФИО, дата рождения, гражданство).
- Отправка данных в очередь на ручную проверку при сомнительном результате.
- Хранение статуса проверки и журнала действий.
- Возможность интеграции с внешними API: Onfido, Sumsub, Veriff, IDnow (через коннектор).

## Модель данных
- `identity_checks`: `id, tenant_id, candidate_id, provider, document_type, status, similarity_score, started_at, completed_at, reviewer_id`
- `identity_check_files`: `id, identity_check_id, file_id, type (document/selfie/ocr_result), created_at`
- `identity_check_logs`: `id, identity_check_id, event_type, message, created_at`

## Логика работы
1. Кандидат загружает паспорт и selfie в Candidate Portal.
2. OCR-сервис извлекает данные (ФИО, дата рождения, номер документа, срок действия).
3. Face Match сравнивает фото с документа и selfie, выдаёт `similarity_score`.
4. Если `score < threshold`, проверка переходит в ручную модерацию.
5. После успешной верификации статус документа обновляется на `verified`.
6. Результаты передаются в модуль **Documents** для подтверждения подлинности.

## API (черновик)
- `POST /identity-checks` — создать запрос на верификацию.
- `GET /identity-checks/{id}` — получить статус.
- `GET /identity-checks` — список последних проверок.
- `POST /identity-checks/{id}/manual-review` — передать на ручную проверку.
- `POST /identity-checks/{id}/approve` — подтвердить вручную.

## UI / UX
- Вкладка **"Проверка личности"** в карточке кандидата.
- Отображаются:
  - Фото документа и selfie.
  - Статус (`pending`, `verified`, `rejected`, `manual_review`).
  - Процент совпадения (`similarity_score`).
  - История проверок и решения модератора.
- Цветовая индикация:
  - 🟢 Verified
  - 🟡 Manual review
  - 🔴 Rejected

## Интеграции
- **Documents:** обновление статусов загруженных документов после успешной верификации.
- **Candidate Portal:** интерфейс для загрузки документов и selfie.
- **Compliance:** результаты верификации фиксируются в отчётах комплаенса.
- **Audit Log:** фиксирует каждое действие и решение модератора.
- **Additional Services:** услуга "Проверка личности" может быть платной для внешних кандидатов.

## Безопасность
- Все изображения и данные проходят анонимизацию (blur лиц, шифрование).
- Доступ имеют только пользователи с ролью `OWNER` или `VERIFIER`.
- Сервисы OCR и Face Match изолированы в отдельном контейнере.
- Метаданные не хранятся дольше 90 дней после завершения проверки.

## Тест-кейсы
- Загрузка документа и selfie → OCR возвращает корректные данные → статус `verified`.
- Несовпадение фото → статус `manual_review`.
- Ручное одобрение администратором → статус `verified`.
- Проверка истёкшего документа → статус `rejected`.
- Проверка RLS: доступ только в пределах tenant.
