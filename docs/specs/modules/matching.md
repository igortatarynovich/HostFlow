

# Matching Engine (Система подбора кандидатов)

## Цель
Автоматизировать процесс подбора кандидатов под вакансии транспортных компаний на основе данных о флоте, маршрутах, документах и опыте.  
Модуль повышает точность подбора, скорость закрытия вакансий и прозрачность логики принятия решений.

## Основные функции
- Автоматический расчёт **рейтинга соответствия (matching score)** между кандидатом и вакансией.
- Фильтрация по ключевым параметрам: документы, тип прицепа, ADR, маршруты, язык, опыт.
- Учет специальных условий (UK/CH маршруты, парные экипажи, работа по B2B).
- Интеграция с Ruleset для проверки обязательных документов и допусков.
- Поддержка ручной корректировки веса критериев.
- Возможность автоподбора — создание предложений кандидату на основе совпадений.

## Модель данных
- `matching_profiles`: `id, tenant_id, candidate_id, vacancy_id, score, matched_at, source, status`
- `matching_rules`: `id, tenant_id, rule_type, weight, field, operator, value, created_at`
- `matching_results`: `id, profile_id, criterion, score, passed, details`

## Логика работы
1. При создании или обновлении вакансии система запускает пересчёт соответствий.
2. Для каждого кандидата формируется набор критериев:
   - наличие обязательных документов (из Ruleset);
   - соответствие категории прав и Code95;
   - опыт работы на нужных маршрутах (EU/UK/CH);
   - ADR-сертификат при необходимости;
   - гражданство/тип разрешения (для правил трудоустройства);
   - язык общения.
3. Каждому критерию присваивается вес (0–1).
4. Итоговый `matching_score` = сумма (вес * результат по критерию).
5. Вакансии и кандидаты с `score >= threshold` отображаются как потенциальные совпадения.
6. При изменении статуса кандидата или вакансии выполняется пересчёт.

## API (черновик)
- `POST /matching/recalculate` — пересчитать соответствия.
- `GET /matching/vacancy/{id}` — список кандидатов с рейтингами.
- `GET /matching/candidate/{id}` — список подходящих вакансий.
- `POST /matching/config` — обновить веса и критерии.
- `GET /matching/rules` — получить текущие правила.

## UI / UX
- В карточке вакансии: список кандидатов с процентом совпадения.
- В карточке кандидата: список подходящих вакансий.
- Фильтры: минимальный процент совпадения, ADR, опыт, язык.
- Визуализация matching-score (progress bar, цветовая шкала).
- Возможность ручного подтверждения совпадения (assign).

## Интеграции
- **Vacancies:** источник требований для критериев.
- **Candidates:** данные кандидата, документы, опыт.
- **Documents:** проверка наличия и актуальности документов.
- **Ruleset:** логика обязательных и рекомендованных требований.
- **Company Profile:** маршруты, флот, тип прицепов.
- **Notifications:** уведомления при нахождении высоких совпадений.
- **Analytics:** статистика по успешным совпадениям и скорингу.

## Безопасность
- Все расчёты выполняются в пределах `tenant_id`.
- Настройки весов и правил доступны только `OWNER`.
- Данные кандидатов и вакансий обезличиваются в аналитике.

## Тест-кейсы
- Пересчёт соответствий для новой вакансии → появляются кандидаты с баллами.
- Отсутствие ADR у кандидата при требовании вакансии → сниженный балл.
- Изменение веса критерия «опыт» → пересчёт рейтингов.
- Автоподбор кандидатов при score > 0.85 → уведомление рекрутера.
- Проверка RLS — видимость совпадений только в пределах tenant.
