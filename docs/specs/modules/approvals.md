# Approvals (Согласования)

## Цель
Управление маршрутами согласования документов, контрактов, счетов и других сущностей. Обеспечивает прозрачность, контроль и юридическую фиксацию всех решений.

## Основные понятия
- **Approval Process** — маршрут согласования (набор шагов и ролей).
- **Approval Step** — отдельный этап с указанием ответственного, статуса и дедлайна.
- **Approval Item** — объект, проходящий процесс согласования (документ, контракт, инвойс).
- **Approver** — пользователь, ответственный за принятие решения на конкретном шаге.

## Применение
- Согласование контрактов с клиентами.
- Проверка счетов перед выставлением.
- Утверждение шаблонов документов.
- Одобрение офферов кандидатов и дополнительных услуг.

## Модель данных
- `approvals`: `id, tenant_id, process_type, related_object_id, status, current_step, created_by, created_at, updated_at`
- `approval_steps`: `id, approval_id, step_order, role, assigned_to, status, comment, due_date, approved_at`
- `approval_roles`: `id, tenant_id, process_type, role_name, order, auto_approve_if_same_user`

## Логика
- Каждый процесс имеет шаблон маршрута, зависящий от `process_type` (например, "contract", "invoice").
- После создания объекта (контракта, инвойса, шаблона) система определяет цепочку согласующих по ролям.
- Каждый шаг можно:
  - **approve** (одобрить)
  - **reject** (отклонить с комментарием)
  - **delegate** (передать другому пользователю)
- При `reject` процесс возвращается на предыдущий шаг или завершается как `rejected`.
- После завершения последнего шага объект получает статус `approved` и может быть опубликован/отправлен.

## API (черновик)
- `POST /approvals` — создать процесс согласования.
- `GET /approvals/{id}` — получить состояние процесса.
- `POST /approvals/{id}/approve` — одобрить текущий шаг.
- `POST /approvals/{id}/reject` — отклонить.
- `POST /approvals/{id}/delegate` — делегировать пользователю.
- `GET /approvals?type=contract` — список процессов по типу.

## UI / UX
- Панель согласований в админке: карточка процесса, шаги, статус, история.
- Уведомления о новых задачах по email и в интерфейсе.
- Возможность комментировать каждый шаг.
- Цветовая индикация статусов:  
  - 🟢 Approved  
  - 🔴 Rejected  
  - 🟡 Pending  

## Интеграции
- **E-signature:** после финального одобрения документ автоматически передаётся на подпись.
- **Invoicing:** инвойсы проходят внутреннее утверждение перед отправкой клиенту.
- **Document Templates:** новые версии шаблонов требуют одобрения.
- **Contracts:** контракт активируется только после полного согласования.
- **Audit Log:** каждое действие фиксируется с подписью пользователя и временем.

## Тест-кейсы
- Создание процесса согласования контракта — маршрут создаётся автоматически.
- Одобрение всех шагов → статус `approved`.
- Отклонение на любом этапе → процесс `rejected`.
- Делегирование шагов с передачей прав.
- Повторное согласование после правок (новая версия объекта).
