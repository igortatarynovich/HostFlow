

# Fin Checks (Финансовые проверки)

## Цель
Модуль предназначен для автоматической проверки финансовой и юридической корректности реквизитов компаний и контрагентов при создании и обновлении записей в системе HostFlow.  
Основная цель — предотвратить ошибки при выставлении счетов и соблюсти требования налогового и бухгалтерского комплаенса в Польше и ЕС.

## Основные функции
- Проверка **NIP**, **REGON**, **KRS** в базе GUS (Polska).
- Проверка **VAT UE** в системе **VIES** (ЕС).
- Проверка банковских счетов в **белом списке Министерства Финансов (Biała Lista)**.
- Проверка статуса **KSeF (e-Faktura)**.
- Валидация IBAN и SWIFT.
- Логирование результатов и статусов проверок.
- Автоматические проверки при создании или изменении компании и перед выставлением счёта.

## Модель данных
- `fin_checks`: `id, tenant_id, company_id, check_type, result_status, result_data, checked_at, created_by`
- `fin_check_logs`: `id, fin_check_id, provider, response_code, raw_response, created_at`

## Логика работы
1. При создании или обновлении компании система запускает проверки:
   - `nip` → GUS API;
   - `vat_eu` → VIES API;
   - `bank_account` → MF Biała Lista API;
   - `ksef_status` → KSeF registry (планируется).
2. Результаты сохраняются в `fin_checks` с пометкой `valid` / `invalid`.
3. Если проверка не пройдена:
   - выставление счёта блокируется;
   - пользователю предлагается подтвердить реквизиты вручную.
4. Проверки можно инициировать вручную через интерфейс.
5. Все результаты логируются в `fin_check_logs`.

## API (черновик)
- `POST /fin-checks` — запустить проверку вручную.
- `GET /fin-checks` — получить список последних проверок.
- `GET /fin-checks/{id}` — детальная информация.
- `GET /fin-checks/company/{company_id}` — история проверок компании.
- `GET /fin-checks/status` — текущие состояния валидности по всем компаниям.

## UI / UX
- Раздел **Финансовые проверки** в карточке компании.
- Отображаются результаты и дата последней проверки.
- Цветовая индикация:
  - 🟢 Всё в порядке (valid)
  - 🟡 Не подтверждено
  - 🔴 Ошибка проверки / Некорректные данные
- Кнопка «Повторить проверку».
- Подсказки и ссылки на официальные реестры (GUS, VIES, MF).

## Интеграции
- **Company Profile:** автоматический запуск проверки при создании или изменении реквизитов.
- **Invoicing:** блокировка выставления счета при ошибочных реквизитах.
- **Compliance:** проверка валидности компаний включается в общий аудит.
- **Audit Log:** запись каждого запроса и ответа от внешнего API.
- **Scheduler:** периодическая перепроверка (раз в 30 дней).

## Безопасность
- Хранение только необходимых данных из ответов API (без чувствительных персональных данных).
- Внешние запросы выполняются через защищённый сервис с лимитами.
- Все ключи и токены API хранятся в Vault.

## Тест-кейсы
- Проверка корректного NIP → статус `valid`.
- Ошибка запроса к VIES → лог в `fin_check_logs`, статус `pending`.
- Проверка неверного номера счёта → статус `invalid`, блокировка инвойса.
- Повторная проверка компании → обновление статуса.
- Проверка RLS — доступ только в рамках tenant.
