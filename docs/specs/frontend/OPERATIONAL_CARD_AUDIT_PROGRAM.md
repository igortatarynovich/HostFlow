## Mandatory Entry Gate (Employee Card)

Before any Employee Card audit starts, complete:

- `EMPLOYEE_CARD_PRE_AUDIT_GATE.md`

Rule:

- if gate result is `PASS`, proceed to Employee Card audit,
- if gate result is `NO BUSINESS CASE`, Employee Card is treated as current baseline and audit branch is not opened.

## Audit Output Per Card

For each target card, produce:

1. Contract validation vs `ENTITY_LAYOUT_V1_DRAFT`
2. Workflow support assessment
3. Read Load / Action Load assessment
4. Strengths / Weaknesses
5. Recommendation: `Adopt / Adapt / Legacy / Reject`
6. Gap list vs Candidate Card baseline

## Governance Rule

No new architecture principles are introduced in this program.

Allowed outcomes:

- apply existing framework,
- identify gaps,
- define adaptation scope for audited card.

## Product Axiom

Do not improve a benchmark without a proven problem.

Interpretation:

- no redesign of a working baseline from theory only,
- change is allowed when there is validated pain, measurable loss, or proven upside.
