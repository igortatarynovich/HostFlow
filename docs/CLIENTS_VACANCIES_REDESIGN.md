# Редизайн клиентов и вакансий

## Исследование

### Лучшие практики CRM для профилей клиентов (recruitment)

1. **Minimal UI** — чёткий, минималистичный интерфейс без лишних элементов.
2. **Иерархия информации** — самое важное сверху: контакт, воронка, быстрые действия.
3. **Свёртываемые секции** — юридические, операционные и прочие детали скрыты по умолчанию.
4. **Контекстные действия** — выставить счёт, отправить по email рядом с карточкой клиента.

### Текущее состояние Companies (клиенты)

**Секции (16+):**
- Hero + KPIs (кандидаты, вакансии, услуги)
- Overview (контакт, финансы, контракты, слоты)
- Vacancies widget
- Blockers widget
- Readiness
- Base (название, контакты, адрес)
- Legal (реестр, VAT, лицензии, адреса, представители)
- Billing (валюта, сроки, invoice_email, банковские счета)
- Contacts
- Operations (парк, режимы, прицепы, маршруты)
- Compliance
- Portal
- Integrations (webhooks, branding)
- Contracts
- Orders
- Document policies
- System

**Проблемы:** слишком много секций, мало контекстных действий (счёт, email).

### Текущее состояние Vacancies

- Список с поиском, фильтрами, сортировкой.
- Структура проще, чем у клиентов.

### Целевая архитектура

1. **Клиенты:**
   - Hero упрощён — без дублирования KPIs.
   - Основное: Overview + контакты + вакансии + счета.
   - Блок «Счета»: список счетов клиента, кнопки «Создать» и «Отправить на email».
   - Вторичные секции (Legal, Operations, Compliance, Portal, Integrations) — collapsible, по умолчанию свёрнуты.

2. **Вакансии:**
   - Привести layout к единому стилю с клиентами (карточки, паддинги, типографика).

3. **API:**
   - `POST /invoices/{id}/send` — уже есть.
   - Добавить на фронте: `sendInvoice(id)`, `getInvoicePdf(id)`.
