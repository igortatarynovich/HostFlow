

# HostFlow LLM Edit Protocol

## Цель
Минимизировать расход токенов и повысить точность изменений при редактировании файлов HostFlow.  
Каждая операция редактирования выполняется строго в формате **delta-only** — добавляется или изменяется только то, что необходимо, без повторения неизменённых частей.

---

## 1. Основной принцип: Delta-only
- НИКОГДА не повторяй весь файл.  
- Указывай только **разницу (diff)** — что добавить, удалить или заменить.  
- Используй точные текстовые якоря (например: «после строки, начинающейся с…»).  
- Если требуется заменить раздел — опиши чётко границы: начальный и конечный заголовок.

Пример:
```
<instructions>
- Найди раздел, начинающийся с "# 22. Logistics Rules".
- Замени его на новый текст:
  ```
  # 22. Logistics & Travel Rules
  - При достижении этапа `Планируем приезд` создаётся поездка.
  - После завершения — статус `На базе клиента`.
  ```
</instructions>
```

---

## 2. Контекст и якоря
Перед изменениями агент обязан:
1. Подтвердить путь к открытому файлу.
2. Работать ТОЛЬКО с этим файлом.
3. Упоминать конкретные строки, заголовки или уникальные фразы, чтобы не было ошибок позиционирования.

Используемые форматы:
- `# Заголовок` — для Markdown
- `CREATE TABLE` или `ALTER TABLE` — для SQL
- `"path":` — для YAML/JSON

---

## 3. Формат инструкции
Всегда использовать синтаксис:
```
<instructions>
- Описание конкретных действий (добавить/заменить/удалить).
- Приведи полный новый фрагмент.
- Не включай пояснений, только фактические шаги.
</instructions>
```

---

## 4. Правила контекста
- Не обращаться к внешним файлам, кроме текущего.
- Не ссылаться на документацию вне `/docs/` (всё доступно через context_map.yml).
- Для длинных разделов использовать сниппеты из `/docs/_llm/snippets/` вместо повторения текста.
- Если изменение касается нескольких файлов — выполнять поочерёдно, **один файл за раз**.

---

## 5. Ограничение по длине
- Максимальный размер одной операции — **до 700 токенов текста изменений**.
- Если правка больше — разбивай на несколько последовательных инструкций.

---

## 6. Типовые операции
- **Добавить раздел:** только новый блок, с заголовком и содержимым.
- **Заменить раздел:** указать границы и вставить новый текст.
- **Удалить раздел:** описать точный диапазон по заголовкам.
- **Обновить значение:** заменить только изменённые строки.

---

## 7. Проверка результата
После каждой правки агент:
1. Подтверждает успешное применение.
2. Кратко сообщает, какие разделы или элементы изменены (до 2 строк).

---

## 8. Примеры лаконичных изменений
✅ Правильно:
```
- Найди раздел "# 18. Compliance Rules".
- Добавь под ним:
  ```
  # 19. Financial Rules
  - Проверка NIP, REGON и VAT перед выставлением счёта.
  ```
```

❌ Неправильно:
- Повторять весь файл.
- Добавлять описания изменений.
- Переписывать уже существующие разделы без причины.

---

## 9. Интеграция с context_map.yml
- Все ссылки внутри изменений должны использовать ID-якоря из `context_map.yml`.
- Если ID отсутствует — создать его при следующей итерации в этом же файле.

---

## 10. Цель оптимизации
Этот протокол позволяет:
- Сократить количество токенов при каждой правке на 80–90%.
- Повысить точность позиционирования изменений.
- Упростить анализ diff-логов и версионирование.
